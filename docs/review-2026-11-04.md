# 全项目检查与优化记录（2026-11-04）

> 本记录中的修复随 **v1.0.8** 发布，发布说明见 [v1.0.8](releases/v1.0.8.md)。

本轮目标是「逻辑清晰、职责明确、功能闭环、无低级错误」。下面按严重程度列出**已确认并修复**的
问题；每条都写明触发条件与改动位置，便于复核。最后单列验证结果与环境限制。

审查覆盖：应用装配与生命周期、认证授权与 CSRF、页面路由、`/api/v1`、对比计算、导入与导出、
规格书识别与提交、数据迁移、审计与保留策略、模板与原生 JS、容器入口、CI 与文档。

---

## 1. 高：会导致 500、数据丢失或功能不可用

| # | 问题 | 触发与影响 | 修改 |
|---|---|---|---|
| 1 | 变更日志关键词只有空白时 500 | `/admin/logs?q=+`、`/api/v1/audit?q=%20`：`search.normalize` 返回 `None`，`pattern(None)` 在 `escape_like` 里 `.replace` 抛 `AttributeError` | `audit.query` 先归一，空关键词等价于「不筛」（`backend/app/audit.py`） |
| 2 | `seed --force` 在已有客户采用记录时崩 | `_clear` 没删 `adoptions`，SQLite 开了 `PRAGMA foreign_keys=ON`，删 `products` 时 `IntegrityError`；而这正是运维会用 `--force` 的场景 | `_clear` 按「引用方 → 被引用方」顺序批量删除（`backend/app/seed.py`） |
| 3 | 空库无法在页面上建第一家公司 | 「新建型号」的公司下拉为空，空库提示却写着「在产品管理里手工建公司」—— 该入口根本不存在 | 新增 `POST /companies` 与产品管理页表单；挡住同名与第二个 `self`（`routes_products.py`、`products.html`） |
| 4 | 客户采用只能新增/删除，不能改进度 | README 把状态定义为「进度」，但页面上从「送样」到「量产」只能删了重建，审计里看起来像换了一家公司 | 新增 `POST /products/{id}/adoptions/{aid}` 与行内编辑器，按状态/年份/备注记差异（`routes_products.py`、`product_edit.html`） |
| 5 | 导入模板多出两列空白 | `TEMPLATE_EXAMPLE` 每行 24 列、表头 22 列，下载的 xlsx/csv 尾部有两列无名空列 | 示例行补齐到与 `WIDE_HEADERS` 同宽（`importer.py`） |

## 3. 低：死代码、命名、格式与文档

- 删除死代码：`importer.REQUIRED_META` 定义未用（改为 `_map_header` 的唯一来源）、
  `routes_datasheet.SHEET_EXT`、`mcp/cib_mcp.py` 里不可达的 `is_notification` 分支、
  CSS 的 `.actions` / `.panel-head.with-search` / `.ds-resolve.ready` / 被覆盖的 `.picker-search`。
- `main.py`：删掉与 `routes_auth` 重复的孤立注释；抽出 `_is_api_v1()` 统一三处路径判断；
  405 的错误码从 `VALIDATION_FAILED` 改为 `METHOD_NOT_ALLOWED`；补全处理函数之间的空行；
  `/datasheet/{id}/file` 的「非 HTML」判定收窄，不再把任意 `*/file` 都算接口。
- `ensure_bootstrap_admin` 改为返回 `(账号名, 密码)`，启动日志不再各读一次环境变量。
- `api_schemas.TokenIn.scopes` 去掉可变默认值。
- `audit._s` 改名 `as_text`（路由层也在用，私有名不再合适）。
- `models.py` 里「声表滤波器」「µL 级流量」等过时描述改为当前口径；`selection.py` 错位的
  「登录 / 登出」分节注释归位。
- `web_shared` 移除公司/型号查找（已下沉 `lookups`），模块职责收窄为「模板环境 + 权限依赖 + 表单校验 + 跳转」。
- 文档：README 的 MCP 工具数 14 → 19、补充 `/companies` 与采用关系路由；
  `docs/AI-API-设计.md` 里「不做审计日志」「不透传 If-Match」两处与实现相反的表述已改正。

## 4. 验证

本轮在 Windows + Python 3.12 上实际执行：

- `ruff check backend/app backend/tests mcp scripts`：通过。
- 纯逻辑测试（compare / units / datasheet / retention / 新增 data_integrity）：**85 项通过**。
- 新增 `backend/tests/test_data_integrity.py`（8 项）：模板列宽、空白关键词、完整度容错、
  公司名括注归一、新建公司去重、采用进度审计、系统设置本地时间、`seed --force` 外键顺序。
- 前端 JS：`test_filter.js` 8/8、`test_datasheet_ui.js` 12/12（含新增括注归一用例）。
- 以 `StrictUndefined` 直接调用 9 个页面路由渲染：全部 200 且无未定义变量
  （含新增的公司表单与采用编辑器）；空库 `empty.html` 亦通过。
- 定向脚本复核：空白关键词不再抛错、`seed --force` 在有采用关系时成功、分页链接对 `A&B` 编码为
  `A%26B`、60 条日志出现分页、模板列宽 22。

**未能在本机执行**：依赖 `TestClient` / uvicorn 的 HTTP 层用例。该环境里 `asyncio` 事件循环无法启动
（最小 `asyncio.run()` 即挂起），与代码无关；Docker 与 PostgreSQL 也不可用。
因此上表 1–19 中涉及 HTTP 状态码/跳转的部分，建议在 CI（Ubuntu）或部署机上跑一遍全量
`pytest backend/tests` 与 `docker compose config` 复核。

## 5. 仍建议（本轮未做）

| 优先级 | 建议 | 原因 |
|---|---|---|
| 中 | 写通道统一数据库级并发版本 | `If-Match` 与写入之间仍有时间窗；多副本/高频并发时需要版本列或事务锁 |
| 中 | `/changes` 补删除事件与产品元信息事件 | 目前只覆盖仍存在的参数，完整镜像同步仍需定期全量核对 |
| 中 | PostgreSQL 集成测试与容器启动验收 | 方言、唯一索引、事务行为不能只靠 SQLite 证明 |
| 低 | 大文件解析移出请求事件循环 | 页数/体积上限限制了单次资源，但大文件仍会占住工作线程 |
| 低 | 依赖锁定与自动升级 PR | 目前除 PyMuPDF 外都是范围约束，升级结果不可复现 |
| 产品 | 新闻动态、趋势、多条件透视、行级数据域 | README 已明确列为未实现，属于后续立项 |
