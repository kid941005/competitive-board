# v1.0.7 — 安全、数据一致性与可靠性修复

本版本修复浏览器 API 写入、PDF 导入、旧库迁移和增量同步中的问题，并统一产品详情响应、导出防护与 MCP 请求处理。

## 主要修改

- Cookie 登录态调用 API 写接口时统一校验 CSRF；Bearer 机器调用保持可用。
- 修复规格书结果的动态 HTML 转义，完善文件标识、元数据和存储异常处理。
- 修复 `.pdf.tmp` 被当作文本解析的问题；并发上传使用独立临时文件。
- 固定 PyMuPDF 为验证通过的 1.26.7，避免自动升级到 2.x 引入布局推理栈和运行故障。
- 旧库型号去重保留内部空格，并迁移客户采用关系；数据库结构升级包含幂等请求指纹（schema v7）。
- 增量接口提供时间 + 记录 ID 的稳定游标，避免相同更新时间下重复卡页。
- 产品 GET/PATCH 使用一致的详情表示，ETag 覆盖参数、来源、公司和采用关系等完整响应字段。
- Excel/CSV 导出保护公式形态文本，Excel 导出处理非法 XML 字符。
- 修复多值单元格跳过单位换算、非有限数及换算溢出等边界。
- MCP 校验错误消息结构，支持 `idempotency_key` 和产品修改的 `if_match` 参数。
- 统一来源引用回收、导入事务、dry_run 和幂等规则；完善删除和孤儿文件清理。
- 独立 API 请求模型与共享导出安全模块，更新 CI、接口文档及完整项目审查报告。

## 升级注意事项

- 升级前备份数据库和 datasheets 原文目录。结构会自动迁移至 schema v7，旧镜像不能直接打开更高版本的数据库。
- 使用 Cookie 调试写 API 的脚本须携带页面中的 `X-CSRF-Token`；使用 Bearer 的客户端不需要该头。
- 增量分页保留初始 `since`，将 `meta.next_cursor` 原样传回 `cursor`。该接口仍只包含当前存在的参数新增/更新，产品元信息与删除需要全量核对。
- MCP 修改产品时，可将 `get_product` 返回的 `meta.etag` 作为 `if_match`。支持幂等的创建和导入工具可传 `idempotency_key`。
- ETag 的计算方式已更新，升级后应重新 GET 资源取得最新版本。
- 已有同内容上传和业务数据保持兼容；公式形态文本导出为文本，XML 禁止字符替换为 `�`。
