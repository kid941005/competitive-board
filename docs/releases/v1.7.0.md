# v1.7.0 — 友商关键词检索与 Agent 推送开放 API

本版补上两条“让市场消息更完整”的通道：一是按友商公司名一键生成 Google News 检索源，二是开放 `POST /api/v1/news`，让 Agent / 脚本把抓到的市场新闻直接推进看板。
数据库仍是 **schema v9**，不新增迁移；页面路由与既有 `/api/v1` 接口保持兼容，新增的只是消息源类型与一个推送端点。

> GitHub Release 的 Latest 与容器镜像 `latest` 均指向 `1.7.0`。
> 从 v1.6.1 升级只需换镜像标签，无需备份迁移；回滚同理。

## 主要修改

### 高：按友商公司名生成检索源

- `/admin/news` 新增「按友商公司名生成检索源」面板：把 `Entity.kind = competitor` 的公司按中文名 / 英文名各生成一条 Google News 检索源。
- 语言可选 **中文 / 英文 / 两者**；默认值跟随系统设置 **新增消息源默认语言**（`news.default_lang`）。
- 同名或同 URL 已存在时跳过，不会生成重复源；客户与自家公司不参与生成。
- 生成结果写入变更日志（对象类型 `news_source`），管理页可继续编辑、停用或删除。

### 高：Agent 推送开放 API（`POST /api/v1/news`）

- 新增 `POST /api/v1/news`，需要 `ingest` scope 的 Bearer 令牌；单次最多 50 条，支持 `dry_run` 预演与 `Idempotency-Key` 重放。
- 每条消息支持 `title`（必填）/ `url` / `summary` / `published_at` / `entity_id` 或 `entity_name` / `lang` / `guid`。
- 推送条目统一挂在固定源 **Agent 推送**（`url=agent://push`、`kind=push`）上；该源不参与自动抓取，管理页只读展示，避免手工和自动抓取互相覆盖。
- 去重沿用全项目同一套规则：有链接用 `sha1(归一化链接)`，无链接用 `sha1(源:id|guid)`；重复推送返回 `duplicated`，不会重复入库。
- 公司可传 `entity_id` 或精确的 `entity_name`；传了但找不到时整批返回 `NOT_FOUND` 并提示，不会静默写成无归属。
- 成功写入的条目记入变更日志（对象类型 `news_item`，`origin=api`），带请求 ID 便于与运行日志对上。
- `GET /api/v1/tools` 的能力清单已同步加上该端点，MCP / function-calling 客户端可直接发现。

### 低：测试与文档

- 新增 `test_news_push.py` 8 项：创建/复用推送源、utm 去重、只读令牌 403、非法 URL 422 且无半写、`dry_run` 不写、`Idempotency-Key` 重放、未知公司 404、无链接 guid 去重。
- 新增 `test_news_company_sources.py` 2 项：页面生成面板、按友商生成两条源、重复不新增、客户不生成，以及 `company_source` 的 URL 编码。
- README 增加「友商公司名作为关键词」「Agent 推送」说明与接口示例。

## 兼容性

| 项目 | 变化 | 说明 |
|---|---|---|
| 数据库结构 | 不变（v9） | 无新表、无新列、无迁移 |
| 页面路由 | 新增管理面板 | `/admin/news` 多一个「按友商公司名生成检索源」表单；既有页面不变 |
| `/api/v1` | **新增** `POST /api/v1/news` | 既有接口请求/响应未改；旧令牌不受影响 |
| 令牌 scope | `ingest` 语义扩展 | 原「按行导入」之外，也可推送市场消息；如不希望某令牌写消息，请勿授予 `ingest` |
| 消息源类型 | 新增 `kind=push` | 只有开放 API 会创建；不参与自动抓取 |
